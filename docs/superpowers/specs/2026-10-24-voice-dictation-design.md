# Голосовой ввод (режим «Диктовка»): дизайн

Дата: 2026-10-24. Статус: согласован в обсуждении, ждёт просмотра.

## Цель

Пользователь нажимает сочетание клавиш, говорит, и через пару секунд в поле ввода, где стоит курсор, появляется чистый текст: без слов-паразитов, повторов и оговорок, со знаками препинания. Работает в любом приложении (Telegram, браузер, Word, почта).

Распознавание речи **локальное**, как и вся обработка текста в Gloss: звук и текст никуда не отправляются. Основной язык русский.

Критерий успеха: «нажал, сказал фразу с паразитами, отпустил, через 1–4 с в поле аккуратный текст с тем же смыслом и словами говорящего».

## Решения, принятые в обсуждении

| Вопрос | Решение |
|---|---|
| Как запускать | Одно сочетание, два способа: короткое нажатие включает запись до следующего нажатия, удержание работает как рация |
| Что делать с речью | Один режим «Диктовка»: убрать паразиты, повторы и оговорки, расставить знаки, не пересказывать |
| Чем распознавать | GigaAM v3 (Сбер) через sherpa-onnx, локально на процессоре |
| Как ставить | Всегда, вместе со всем остальным; у пользователей 1.0.0 докачивается при первом запуске новой версии |

Отклонённые варианты: Whisper (whisper.cpp) хуже распознаёт русский, весит 0,5–1,6 ГБ, без официальных сборок Vulkan под Windows; встроенный голосовой ввод Windows (Win+H) отправляет звук в облако Microsoft и плохо понимает русский.

## Поведение для пользователя

- **Сочетание** по умолчанию `Ctrl+Alt+Space`, меняется в окне «Сочетания клавиш…» наравне с режимами. Режим можно выключить. В меню значка пункт «Диктовка» с сочетанием.
- **Короткое нажатие** (клавиша отпущена быстрее `TAP_MAX_SEC` = 0,4 с): запись идёт до следующего нажатия сочетания.
- **Удержание** (клавиша держится дольше 0,4 с): запись идёт, пока клавиша нажата.
- **Во время записи** у курсора плашка «🎙 Слушаю… 0:07» с индикатором громкости, на значке кольцо. Затем плашка «Распознаю…», потом «Улучшаю…».
- **Esc** отменяет запись, распознавание или улучшение; в поле ничего не вставляется.
- **Результат** вставляется в позицию курсора через буфер обмена (Ctrl+V), исходное содержимое буфера возвращается. Выделенный в поле текст заменяется, как при обычном вводе.
- **Предел записи** 5 минут (`max_record_sec`), после него запись останавливается сама и обрабатывается.
- **Тишина** (речи не обнаружено): плашка «Не расслышал», ничего не вставляется.
- **GigaChat недоступен**: вставляется распознанный текст без улучшения, уведомление «Вставил текст без улучшения: модель недоступна».
- Пока идёт обычная обработка выделенного текста, диктовка не запускается, и наоборот (одна задача за раз, как сейчас).

### Что делает режим «Диктовка»

- убирает слова-паразиты и звуки колебания: «ну», «короче», «как бы», «типа», «вот», «это самое», «э-э», «м-м»;
- убирает повторы и самоисправления: «в три, нет, в четыре» → «в четыре»; «я хотел, я хотел сказать» → «я хотел сказать»;
- исправляет знаки препинания и заглавные буквы (GigaAM с пунктуацией ставит их сама, GigaChat поправляет);
- делит длинную речь на абзацы по смыслу;
- **не пересказывает**: слова, порядок мыслей и стиль говорящего сохраняются, факты не добавляются;
- не отвечает на сказанное: «напиши письмо Ивану» вставляется как текст, а не выполняется.

## Компоненты

### `mic.py`: запись с микрофона

- WinAPI `waveInOpen` / `waveInPrepareHeader` / `waveInAddBuffer` / `waveInStart` / `waveInStop` / `waveInReset` / `waveInClose` через ctypes; объявления добавляются в `winapi.py`. Устройство `WAVE_MAPPER` (микрофон по умолчанию в Windows).
- Формат 16 кГц, моно, 16 бит (PCM), именно его ждёт GigaAM. Буферы по 100 мс, уведомления через `CALLBACK_EVENT`, чтение в отдельном потоке.
- Интерфейс: `Recorder.start()`, `Recorder.stop() -> bytes` (сырой PCM), `Recorder.level() -> float` (0..1, громкость последнего буфера для плашки), `Recorder.elapsed() -> float`.
- Ошибки: `MicError` с понятным текстом. `MMSYSERR_BADDEVICEID` / `MMSYSERR_NODRIVER` → «Микрофон не найден»; `MMSYSERR_ALLOCATED` → «Микрофон занят другой программой». Если запись идёт, но все буферы нулевые (доступ запрещён в «Параметры → Конфиденциальность → Микрофон», Windows в этом случае отдаёт тишину), после записи выдаётся подсказка, где включить доступ.
- Чистые функции без WinAPI, покрываются тестами:
  - `rms(pcm) -> float`;
  - `has_speech(pcm) -> bool`: есть ли хотя бы ~0,3 с сигнала выше порога;
  - `split_on_pauses(pcm, max_sec=20) -> list[bytes]`: режет запись по самым тихим местам так, чтобы куски были не длиннее `max_sec`; без пауз режет жёстко по `max_sec`;
  - `to_wav(pcm) -> bytes` через стандартный модуль `wave`.

### `speech.py`: распознавание

По образцу `engine.py`.

- Закреплённые файлы (сверка по SHA-256 при загрузке):

| Файл | Размер | SHA-256 |
|---|---|---|
| `sherpa-onnx-v1.13.8-win-x64-shared-MT-Release-no-tts.tar.bz2` | 22,2 МБ | `4b0a94f7b5c606b1b64a19a831c2127559e4b3d34e195465ebc7be73d9ed4783` |
| `sherpa-onnx-v1.13.8-win-arm64-shared-MT-Release-no-tts.tar.bz2` | 20,9 МБ | `29a864324e658bef2a8b83bd3e12adae8b415a5a232d83902030e8c6efa37dbc` |
| `sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16.tar.bz2` | 162,3 МБ | `f9620a0099019c6afcee26525ef9ed3297fa50dd5691c1902af0c948fc1a470b` |

  Источник: выпуски `k2-fsa/sherpa-onnx` на GitHub (тег `v1.13.8` для движка, тег `asr-models` для модели). Свежая v2.0.0 (вышла 2026-10-23) сознательно не берётся.
- Установка в `data_dir()/speech`: из архива движка берутся только `sherpa-onnx-offline.exe` и нужные DLL, из архива модели только файлы модели и `tokens.txt`. Распаковка через стандартный `tarfile` во временную папку, затем переименование, чтобы не оставить полусобранную установку. В папке лежит файл-метка с версией (`ASR_BUILD`), по ней `is_installed()` понимает, что ставить заново не нужно. Загрузка докачивается после обрыва, как у модели (`model_files.py`).
- `transcribe(pcm, cancel) -> str`: режет запись `split_on_pauses`, пишет куски во временные WAV, запускает `sherpa-onnx-offline.exe` один раз со всеми файлами (параметры transducer: `--encoder`, `--decoder`, `--joiner`, `--tokens`, `--model-type=nemo_transducer`, `--num-threads` по числу ядер, но не больше 4), без окна (`CREATE_NO_WINDOW`), в Job Object как llama-server. Отмена: `cancel` убивает процесс. Разбор вывода в отдельной чистой функции `parse_output(stdout) -> list[str]` (текст по каждому файлу в порядке подачи), куски склеиваются через пробел.
- Ошибки: `SpeechMissing` (не установлено или файлы повреждены), `SpeechError` (процесс упал, код возврата и хвост stderr в журнал).
- Первый шаг реализации (замер): скачать файлы, проверить точные параметры командной строки и формат вывода v1.13.8, замерить время на 5-секундной и 60-секундной записи. Если загрузка модели при каждом запуске дольше ~1,5 с, `speech.py` переходит на `sherpa-onnx-offline-websocket-server.exe`, который держит модель в памяти (запуск по требованию и выгрузка после простоя, как у llama-server). Интерфейс `transcribe` при этом не меняется.

### `dictation.py`: логика клавиши

- `RegisterHotKey` сообщает только о нажатии. После `WM_HOTKEY` поток опрашивает `GetAsyncKeyState` основной клавиши сочетания каждые 20 мс, как `capture.py` ждёт отпускания модификаторов.
- Чистый автомат состояний без WinAPI, на поддельных часах в тестах: состояния `idle → pressed → (held | latched) → finishing`. События: «сочетание нажато», «клавиша отпущена», «Esc», «превышен предел». Выход: «начать запись», «закончить и обработать», «отменить».
  - отпустили раньше `TAP_MAX_SEC` → `latched`, запись продолжается до следующего нажатия;
  - держат дольше `TAP_MAX_SEC` → `held`, отпускание заканчивает запись;
  - повторное нажатие в `latched` → закончить и обработать;
  - автоповтор `WM_HOTKEY` при удержании игнорируется (`MOD_NOREPEAT`).

### Режим «Диктовка»: `modes.py` и `config.json`

- Новая секция `dictation` в `config.json`, отдельная от списка `modes`, потому что режим работает не с выделением:

```json
"dictation": {
  "name": "Диктовка",
  "hotkey": "ctrl+alt+space",
  "enabled": true,
  "temperature": 0.2,
  "max_record_sec": 300,
  "prompt": ["…"]
}
```

- Промпт по-английски, как остальные (см. докстринг `modes.py`). Общие правила `common_rules` применяются и к нему. Черновик:
  - Task: the text is an automatic speech transcript. Remove filler words and hesitation sounds (ну, короче, как бы, типа, вот, это самое, э-э, м-м), false starts, stutters and repeated words. When the speaker corrects themselves, keep only the corrected version.
  - Fix punctuation and capitalization; split long text into paragraphs by topic.
  - Keep the speaker's own words, word order, tone and meaning. Do not paraphrase, summarize or add anything.
- `config.py`: загрузка и проверка секции; значения по умолчанию, если секции нет (у пользователей 1.0.0 её нет). Сочетание проверяется на конфликт с сочетаниями режимов.
- `hotkeys_window.py`: строка «Диктовка» в окне «Сочетания клавиш…».

### `main.py`: сценарий `_dictate`

1. Взять ту же блокировку задачи (`_job_lock`), что и обычные режимы. Если занято, ничего не делать.
2. Проверить `speech.is_installed()`; если идёт фоновая докачка, плашка «Распознавание речи ещё загружается».
3. Начать запись, показать плашку «Слушаю…» с таймером и громкостью, кольцо на значке.
4. По сигналу автомата из `dictation.py` остановить запись. При отмене выйти.
5. `has_speech` ложно → «Не расслышал», выйти.
6. `speech.transcribe` → сырой текст. Пустой → «Не расслышал».
7. `llm.process(text, dictation_mode, …)` с той же очисткой ответа (`clean_output`) и отменой по Esc. При `BackendUnavailable` / `ModelMissing` / `LlmError` взять сырой текст и показать уведомление.
8. Вставить через `TextCapture.paste_text` (новый метод).
9. Записать в журнал длительность записи и время каждого этапа (без самого текста).

Сырой PCM и временные WAV не сохраняются на диск дольше, чем нужно для распознавания; временная папка удаляется в `finally`.

### `capture.py`: только вставка

Новый метод `TextCapture.paste_text(text)`: дождаться отпускания модификаторов, сохранить буфер, положить текст, Ctrl+V, вернуть буфер. Использует уже существующие части текущей схемы «скопировать → заменить», без Ctrl+C.

### `ui.py`: плашка

Запись показывается существующей плашкой у курсора: заголовок «Gloss · Диктовка: слушаю», строка `0:07 ▮▮▮▮▯▯▯▯ · Esc: отменить` с полосой громкости из символов, обновление ~10 раз в секунду из `Recorder.level()`. Новый метод `Ui.flash` показывает короткие сообщения («Не расслышал») и сам скрывает плашку через 2 с.

## Установка, обновление, удаление

- **Установщик** (`setup_steps.py`, `installer.py`): новый шаг `speech` «Распознавание речи» после шага `model` и до `gloss`, выполняется и при `builtin`, и при `ollama`. Уже установленное пропускается.
- **Проверка компьютера** (`sysinfo.py`): строка «Распознавание речи: GigaAM v3, будет скачано (185 МБ)» или «уже установлено»; размер учитывается в проверке свободного места.
- **Обновление с 1.0.0**: при запуске, если `speech.is_installed()` ложно, Gloss докачивает в фоне по образцу `App._install_engine`. Новая версия sherpa-onnx или модели в будущих выпусках Gloss ставится так же, по смене `ASR_BUILD`.
- **Удаление** (`system.perform_uninstall`): папка `data_dir()/speech` добавляется в список удаляемых вместе с движком (`engine_dirs()`); `system.stop_engine()` также останавливает зависший `sherpa-onnx-offline.exe`.
- **Песочница**: `GLOSS_SANDBOX` распространяется на шаг `speech`.

## Результаты замера (задача 1 плана, 2026-10-24)

Проверено на x64, Windows 11, 4 потока, синтезированная речь (голос SAPI «Irina», 16 кГц моно).

**Файлы, которые нужны.** Из архива движка: `bin/sherpa-onnx-offline.exe` и `bin/onnxruntime.dll` (без `onnxruntime_providers_shared.dll` и без `lib/` всё работает). Из архива модели (папка `sherpa-onnx-nemo-transducer-punct-giga-am-v3-russian-2025-12-16/`): `encoder.int8.onnx` (224,6 МБ), `decoder.onnx`, `joiner.onnx`, `tokens.txt`, `LICENSE`. На диске после установки около 241 МБ.

**Командная строка.**

```
sherpa-onnx-offline.exe --tokens=model/tokens.txt --encoder=model/encoder.int8.onnx --decoder=model/decoder.onnx --joiner=model/joiner.onnx --model-type=nemo_transducer --num-threads=4 tmp/1.wav tmp/2.wav
```

**Вывод.** stdout: по одной строке JSON на каждый файл, в порядке подачи, в UTF-8; текст в поле `"text"`, для тишины `""`. stderr: отладочная информация (конфигурация, «recognizer created in N s», имена файлов, «Elapsed seconds»). Код возврата при ошибке `-1` (4294967295).

**Пути с кириллицей не работают.** Если в аргументах есть кириллица (папка пользователя `C:\Users\Семён`, имя файла), sherpa-onnx пишет «does not exist» даже при кодовой странице 1251. Работает так: рабочая папка процесса `speech_dir()` (кириллица в ней допустима), все аргументы относительные и только латиницей: модель в `model/`, временные WAV в `speech_dir()/tmp` с именами `1.wav`, `2.wav`. Поэтому временные файлы пишутся не в `%TEMP%`, а в `speech_dir()/tmp`, и папка очищается в `finally`.

**Скорость.**

| Запись | Время |
|---|---|
| Загрузка модели | 0,93–1,06 с |
| 5 с речи | ≈1,3 с всего |
| 11 с речи | 0,38 с распознавания (≈1,5 с всего) |
| 83 с речи одним файлом | 12,0 с распознавания |
| 83 с речи кусками по 20 с в одном запуске | 3,7 с распознавания (4,7 с всего) |
| 3 с тишины | 0,12 с, текст пустой |

Решение: **запуск на каждую диктовку** (загрузка около 1 с, меньше порога 1,5 с), websocket-сервер не нужен. Нарезка на куски до 20 с обязательна: длинная запись одним куском в 3 раза медленнее.

**Качество.** GigaAM v3 сама ставит знаки препинания и заглавные буквы: «Ну, короче, завтра созвон в три. Нет, в 4.» Паразиты («ну», «короче», «э-э», «типа», «как бы») распознаёт как слова, их убирает GigaChat. Числа иногда пишет цифрами («в 4»). На стыке кусков, разрезанных посреди слова, слово может повториться в обоих кусках, а кусок начинается с заглавной буквы; при разрезе по паузе этого нет, остальное исправляет GigaChat.

**Пакет из файлов разной длины.** Пакет из кусков не длиннее 20 с даёт тот же текст, что и распознавание по одному. Но в пакете с 83-секундным файлом короткая фраза потеряла конец. Ещё одна причина держать куски не длиннее 20 с. Короткий хвост в конце куска без паузы распознаётся надёжнее, если добавить 0,25 с тишины в начало и конец каждого куска: `transcribe` так и делает.

**ARM64** не проверялся (нет устройства); сборка устроена так же.
